Reason: the Saturday run queries `PositionDate >= '<Sat>'` and FundStudio *does* carry a Saturday snapshot (08-08 returned 3,259 rows), while the Sunday run finds none. So on a **Saturday** run, an `[OK]` is the expected result and a FAILURE would be worth a second look; on a **Sunday** run, expect the FAILURE and ignore it. `[FAILURE] fundstudio database checker` (qrtest, in `Inbox/auto`) fires because its query `SELECT ... This is the expected weekend no-position condition (FundStudio has no Sat/Sun portfolio snapshot), NOT a pipeline break, and it is FundStudio portfolio-data infra (fund-services/ops owned), not Howard's model. Do NOT flag it as a concerning failure. Only escalate if `T_FS_PORTFOLIO` is empty on a **business date** (a Monday+ empty result = real load failure).
