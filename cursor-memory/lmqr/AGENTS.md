# AGENTS.md — LMQR Workspace

## Learned User Preferences

- Required model columns should fail loudly; use defensive name guards only for genuinely optional fields or supported aliases such as `OriginalRating` versus `original_rating`.
- Keep CLO features, caps/floors, filters, weights, and hyperparameters in one config source; put reusable helpers in utility files, keep training drivers thin, and preserve interactive RStudio execution for research R scripts.
- Capped or floored features use a `c_` prefix while raw columns retain their original names; config/report keys must use the actual capped column names or plots can be skipped silently.
- Research and test runs must write to separate sandbox paths and dev tables, never overwriting production JSON, production stats tables, or prod jobs. Before release, regenerate the standard artifacts and run the JSON replay/tieout.
- Diagnostic metrics and plots must use the same observation weights as the fitted model; unweighted fits require unweighted diagnostics.
- When extending a production CLO report, preserve its existing formatting and add the requested columns or summary pages instead of replacing it with a new report layout.
- Default to the smallest change that works; expect pushback on extra columns, seed data, validation flags, and compatibility shims, and justify any new guardrail with the concrete failure it prevents. Never commit scratch or test files alongside a production fix.
- The user opens their own PRs and often prefers to run long or production commands himself, so hand over the exact command instead of executing it. Do feature work in a separate worktree rather than switching the main checkout, and publish with `git push -u origin HEAD`, since a worktree branch created from `origin/master` inherits it as upstream and branch protection rejects a push to `master`.
- A definition change is never local: apply it across every product config that shares it (CAS, STACR, MIR, NQM, LP/Jumbo) and their pseudo variants, keep pseudo and core on one shared query instead of divergent copies, and match the R reference implementation in RCode exactly when one exists.

## Learned Workspace Facts

- In R, variable-driven `data.table` selection requires `df[, ..cols]` or `df[, cols, with = FALSE]`; `else` must be on the same line as the preceding `}`.
- For pooled AAA+AA+A GAMs, normalize features with non-overlapping rating distributions by frozen rating-level means (`x / rating_mean`). Use `Rating`, not `f_OrigRating`, because production prediction fields must match `CLOSpreadModelBond`. EUR A-AAA reporting keeps these senior-fit conventions and the shared `research_howard` helpers, including `c_OfferSize` over `1k-4mm`, `c_AAAFactor` over `0.95-1.0`, `weight_mode`, and weighted diagnostics.
- The BBB research filter `MVOC <= 1.03` must never be copied to AAA/AA/A; senior MVOCs are much higher and that filter drops every row. OFFER is the ListingType reference level across GAM and LGBM models.
- `clo_model/procs/clo_dm_based_model_train.py` owns registry-based production training for `v1`, `v2`, `v2r`, and `delev`. `v2r` writes EUR-senior artifacts into the V2 roots, including `S:/QR/Risk/CLOCache/core/dm_based_model_v2/`; `Broad-Prod` now resolves to `GAM_MODEL_CONFIG_V3`, so EUR senior DM-based JSONs are active rather than falling through to the MVOC curve. Classic production GAM training is a separate path: `half_life=30` at the call site in `spread_model/gam.py`, fit with `time_weight` only, without the listing-type multipliers LGBM research uses.
- Production results live in `Libremax_rd.dbo.clo_spread_model_result`. Select the release with outer `ModelName`/`ModelVersion` (`Broad-Prod` is currently `GAM`/`v3.0`), filter the workflow with `Purpose` and `Scenario`, and deduplicate by latest `RunDateTime`, then `RunID`, per security/date. `Purpose` identifies run usage, not the submodel; use `ModelOutputJson` fields such as `sub_model_name` and `sub_model_version` for submodel identity, and expect some EUR-only rows only under `Galileo-*` purposes. Delevered models are price-based and `RiskSpreadModel` already converts model price to risk spread for the outer result, so evaluation must not apply a second DM-to-price conversion.
- Export `scam`/`gam` models with the term classes in `clo_model/model/gam/terms.py` and EUR-senior `mgcv::bam` with `clo_model/model/gam/export_bam_json.R`; production replays JSON through `GAMReplayModel.from_partial_dependence_json()` using PCHIP, with no R dependency at prediction time. The V2R Python config exports features, caps, and hyperparameters to JSON for `clo_dm_based_model_train_r.R`, and Python-to-R calls require an `Rscript` preflight, timeout, captured stderr, and atomic temporary-file rename.
- A CoreLogic LP `factor_date` of month M reports month M-1 activity, while a DV01/Figure platform tape stamped `as_of_date` month-end M reports month M activity, so Figure-sourced HELOC legitimately runs one activity month ahead of NonQM/Jumbo/CRT; settle any "is this column mislabelled?" question by comparing paid-in-full month and modal `loan_interest_paid_through_date` within each tape rather than reasoning from `agencydata/config/resi_date_offsets.py`. Deal-level DV01 accounts then lag the `Figure Platform` account by about a month because `lmdv01/dv01_update_platf.py` inner-joins FIGRE deals to their deal-level account (all except `FIGRE 2023-HE1A2` and `GRADE*`), so GRADE deals and HELOC pseudo pools pick up a new tape first; join the two feeds on `line_of_credit_id` from `mortgage_static_data`, since `dv01_id` is account-scoped and `loan_id_reported` carries a `FIGURE-` prefix only on the platform side, and run the queries through `lmdv01.dv01_utils.execute_dv01_big_query`.
- Model-result rows under the same key carry two payload shapes: nightly ECA rows hold vectors only, monthly rows also hold `ALL.Transition`. Transition consumers must pass `require_transitions=True` to `getLatestCollatScen` in `lmsimvectors/model_run_result_db_manager.py` or the newest row can be an ECA payload and the read fails with a `KeyError`; vector consumers legitimately need the unfiltered path.
- Raw disclosure tables sit months apart, so no job may assume one shared "current factor month": measured on 2026-08-13, `fnma.fnm_crt` was at 202605, `fnma.fnm_sf` at 202509, both `fhlmc` dyn tables at 202606, and `trst.usbank_ll`, `lps.lp_dyn` and the Figure platform at 202607. Drive every query off its own table's `max(date_column)` instead of a current-and-previous-month window, and treat a month as usable only once its row count reaches 90% of the prior month's (the rule already codified in `agencydata/wh_nqm_pseudo_sample.py`), because partial early data lands mid-month. `fnma.fnm_sf` lags about eleven months by design (a slow feed, not a dead table). CRT/product "SF" is Fannie `fnma.fnm_sf`; `fhlmc.fhl_sfll_dyn` / `fhl_sfll_stat` is the separate Freddie Mac loan-level tape (Webb/Hill), not a missing CRT source — do not add it to `lib.servicer_map` unless someone actually fits on that tape.
- `executeSQL(db="padb", ...)` takes the pyodbc branch in `lmdata/lmdb.py` because `WH_DB = "padb"` (around line 852), not the SQLAlchemy `else` path. Autocommit is off and the connection is closed without committing, so DDL/DML silently rolls back unless the SQL ends with `commit;`. Each call still gets a fresh connection, so staging cannot be `TEMPORARY`; use a real table with a unique suffix and drop it in a `finally`. `executeSQLRedshiftDF` is the `redshift_connector` path, so do not cite one as the other. Redshift qualifies `UPDATE` target columns by table name alone (`servicer_map.col`, never `lib.servicer_map.col`) and rejects row-constructor `IN` lists such as `WHERE (a, b) IN ((...),(...))`.
- Run repo commands with the `pyprod` env (`C:/qr/miniconda/envs/pyprod/python.exe`) and `PYTHONPATH` set to the repo root, since a bare `python` resolves to base miniconda. PowerShell `$arr[-1] = x` assigns the last element, so a lookup helper returning -1 on a miss silently overwrites the end of a file; guard the return before indexing. `Read`/`StrReplace` can also act on a stale cached snapshot, so when an edit tool insists text is missing that you know exists, confirm the true line count through the shell before writing.
- Figure publishes no servicer field: `loan_servicer_primary`, `loan_servicer_master`, `loan_seller` and `loan_origination_channel` are entirely blank on `lib.mortgage_static_data_figure_platform`, and `loan_originator` is the only populated identity column (about 17% blank, roughly 22 distinct values). Mapping Figure on `loan_originator` is intentional, not a defect; the core-file `loan_servicer_primary as servicer_name` alias is a later config change, not mapping-table work. Any Figure-sourced servicer variable really means originator. LPS current-servicer for `lib.servicer_map` is `lps.lp_stat.servicer` (`st.servicer`), not the `lps.lp_svcr.servicer_curr` snapshot. LPS text columns such as `servicer`, `pool_id` and `loan_id` are blank-padded `CHAR`, so always `upper(trim(...))` before comparing or grouping.
